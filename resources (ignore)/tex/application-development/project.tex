\section*{Instructions}

\subsection*{Functionality - Learning Outcomes 1, 2 (20\%)}
\begin{itemize}
	 \item Application v1 with the following functionality:
   \begin{itemize}
    \item Data is fetched from a local \textbf{JSON} file.
    \item App icon and splash screen.
    \item Styled using \textbf{Tailwind CSS}.

    \item \textbf{Recipe Details Screen Features}:
    \begin{itemize}
      \item Display the recipe's name, cuisine, image, ingredients, difficulty, prep time, cook time, servings, tags, nutrition, average rating and reviews.
      \item Display a heart icon in the top-right corner. Tapping it adds or removes the recipe and saves the changes.
      \item Display a plus icon next to the heart icon. Tapping it adds or removes the recipe's ingredients and saves the changes, ensuring no duplicate ingredients are stored.
    \end{itemize}

    \item \textbf{Daily Specials Screen Features}:
    \begin{itemize}
      \item Display a list of five randomly selected recipes with difficulty level Easy or Medium.
      \item Each item should show the recipe's name, cuisine, image and average rating.
      \item Tapping an item should navigate to the \textbf{Recipe Details Screen}.
    \end{itemize}

    \item \textbf{All Recipes Screen Features}:
    \begin{itemize}
      \item Display a list of all recipes.
      \item Each item should show the recipe's name, image, difficulty level, total time and average rating.
      \item Tapping an item should navigate to the \textbf{Recipe Details Screen}.
    \end{itemize}

    \item \textbf{Favourites Screen Features}:
    \begin{itemize}
      \item Display a list of saved favourite recipes.
      \item Each item should show the recipe's name, image and average rating.
      \item Tapping an item should navigate to the \textbf{Recipe Details Screen}.
    \end{itemize}

    \item \textbf{Ingredients Screen Features}:
    \begin{itemize}
      \item Display a list of saved ingredients grouped by category.
      \item Each item should display the ingredient name, quantity and category.
      \item Display a trash icon. Tapping it removes the ingredient and saves the changes.
    \end{itemize}
  \end{itemize}

\item Application v2, which builds on v1 with the following functionality:
  \begin{itemize}
    \item Select any four \textbf{Medium Features} from the list below:
    \begin{itemize}
      \item Filter recipes by cuisine, tags, difficulty level and ingredient categories.
      \item Search recipes by name, ingredient name or tag.
      \item Sort recipes by prep time, cook time, total time, difficulty level or average rating.
      \item Dark mode support with a theme toggle.
      \item Delete all saved favourite recipes or ingredients.
      \item Display recipes by times cooked or last cooked.
      \item Display a list of the last five recipes viewed.
    \end{itemize}

    \item Select any four \textbf{Hard Features} from the list below:
    \begin{itemize}
      \item Save and edit notes on recipes.
      \item Add ratings and write reviews for recipes.
      \item View combined ratings and user reviews.
      \item Manage user profiles with preferences and dietary needs.
      \item Add new recipes.
      \item Update and delete existing recipes.
      \item Meal planner to schedule recipes by day.
    \end{itemize}

    \item Choose two features of your choice. These features should be different from the ones listed above.
  \end{itemize}

  \item Create an \textbf{APK} for both v1 and v2.
\end{itemize}

\subsection*{Code Quality and Best Practices - Learning Outcomes 1, 3 (35\%)}
\begin{itemize}
\item Write clean, readable, and maintainable code.
\item Use modular, reusable components and avoid code duplication.
\item Keep code simple and easy to understand.
\item Ensure the applications are responsive across different screen sizes and orientations.
\item Optimise performance by managing resources efficiently.
\end{itemize}

\subsection*{Version Control - Learning Outcome 3 (5\%)}
\begin{itemize}
  \item Regular commits are made throughout development, demonstrating meaningful progress.
  \item Commit messages are clear and descriptive.
  \item The repository shows a clean and logical commit history that reflects the development process of the applications.
\end{itemize} 

\subsection*{Testing - Learning Outcome 3 (10\%)}
\begin{itemize}
  \item Test the applications with three different users for each version (six users total), observing how they navigate and use features.
  \item Collect written feedback on usability issues, confusing UI and bugs.
  \item Write a brief report summarising the user testing, including:
  \begin{itemize}
    \item Tester information (anonymised).
    \item Tasks performed.
    \item Positive feedback received.
    \item Areas for improvement identified.
    \item Bugs or errors found.
    \item Suggestions on how feedback could be used to improve the applications (no requirement to implement).
  \end{itemize}
\end{itemize}

\subsection*{Reflection - Learning Outcomes 1, 3 (5\%)}
\begin{itemize}
  \item Write a short reflection (300-500 words) on your development process and learning throughout the project, including:
  \begin{itemize}
    \item Challenges you faced and how you overcame them.
    \item What you would do differently in future projects.
    \item New skills, tools or practices you learned during the project.
  \end{itemize}
\end{itemize}

\subsection*{Presentation - Learning Outcome 2 (5\%)}
\begin{itemize}
  \item Record a 5-10 minute screen recording of your applications.
  \item Demonstrate the v1 and v2 features.
  \item Make sure the video is clear and easy to follow.
  \item Submit a link to the presentation in your repository's \textbf{README.md} file.
\end{itemize}
